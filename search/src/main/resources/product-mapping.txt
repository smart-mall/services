# product 索引映射（Kibana Dev Tools 里执行）
#
# skuPrice 必须是数值类型（double）。写成 keyword 的后果是排序和区间筛选都会退化成字符串字典序：
#   sort=skuPrice_asc  -> 254.0, 41.0, 4188.0, 452.0 ... （不是数值升序）
#   skuPrice=1000_5000 -> 多算 254/41，漏掉 512/523/565
# 代码那边是对的：MallSearchServiceImpl 用的是 NumberRangeQuery + Double.parseDouble，要求的就是数值区间。
#
# skuTitle 建索引用 ik_max_word、查询用 ik_smart，两个分析器必须分开：
#   ik_smart 只产粗粒度词，「小米 14 智能手机 黑色」整句切成 ['小米','14','智能手机','黑色']，
#   索引里根本没有「手机」这个 token，用户搜「手机」命中 0（「电视」「笔记本」同理）。
#   ik_max_word 会同时产出「智能手机/智能/能手/手机」这类重叠词，子词才搜得到。
#   查询侧仍用 ik_smart：查询串不需要切那么碎，切碎了反而引入噪音。
#
# brandName / brandImg / catalogName / attrs.attrName 不能设 index:false 和 doc_values:false，
# 因为检索结果里的品牌、分类、属性筛选列表是用 terms 聚合算出来的，而聚合依赖 doc_values。
# skuImg 只从 _source 里取，不做检索、排序、聚合，所以保留这两个优化是安全的。
